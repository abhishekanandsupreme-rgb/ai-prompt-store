Show prospects the transformation from amateur prompts to professional-grade prompt packs. Use this in demos, landing pages, and social proof content.

## The Before / After Framework

| Element | Before: Generic Prompt | After: Optimized Prompt Pack |
|---|---|---|
| **Clarity** | Vague, open-ended instructions | Precise role, context, and output format |
| **Context** | Assumed, not stated | Full background, audience, constraints |
| **Structure** | Single paragraph, unstructured | Step-by-step with section headers |
| **Examples** | None or one weak example | Multiple high-quality examples included |
| **Constraints** | Missing | Explicit word count, tone, format rules |
| **Variables** | Hardcoded or missing | `{{variable}}` placeholders for reuse |

| **Output Quality** | Generic, inconsistent, often unusable | Professional, consistent, publish-ready |

| **Reusability** | One-off, hard to adapt | Modular, works across 10+ scenarios |

## Side-by-Side Prompt Comparisons

### 1. Sales Outreach Email

**Before:**
```
Write a sales email to a potential client about our product.
```

**After:**
```
# Role
You are a B2B sales copywriter specializing in SaaS outreach. You write concise, value-driven emails that get replies.

# Context
- Product: AI-powered project management tool
- Target: Marketing directors at 50–200 person agencies
- Pain point: Teams waste 10+ hours/week on status updates
- Offer: Free 14-day trial with dedicated onboarding

# Output Format
Subject line only — no greeting, no signature, no extra text.

# Constraints
- Subject line max 60 characters
- Include one specific number or stat
- Avoid spam trigger words (free, guarantee, act now)
- Sound like a colleague, not a salesperson

# Examples
Good: "Your team spends 10 hrs/week on status updates — cut it to 2"
Bad: "Revolutionary project management software — limited time offer!"
```

**Why it works:** Role + context + constraints = predictable, high-quality output.

### 2. Code Review

**Before:**
```
Review this code for bugs.
```

**After:**
```
# Role
Senior code reviewer at a top-tier tech company. You are thorough, constructive, and prioritize security and performance.

# Task
Review the following code for:
1. Security vulnerabilities (OWASP Top 10)
2. Performance bottlenecks
3. Code smells and maintainability issues
4. Missing error handling

# Output Format
For each issue:
- Severity: Critical / High / Medium / Low
- Location: File and line number
- Issue description
- Suggested fix with code example
- Rationale

# Tone
Professional and educational. Explain why something is a problem, not just that it is.

# Code to Review
```
[code block]
```

# Constraints
- Do not rewrite the entire file
- Prioritize security issues over style issues
- If no issues found in a category, state "None found"
```

**Why it works:** Explicit categories + output format = structured, actionable review.

### 3. Marketing Blog Post

**Before:**
```
Write a blog post about remote work productivity.
```

**After:**
```
# Role
Content strategist and SEO writer. You create blog posts that rank on page 1 and keep readers engaged to the end.

# Topic
Remote work productivity tips for distributed teams

# Target Audience
Startup founders and team leads managing 5–30 person remote teams

# Structure
1. Hook (personal anecdote or surprising stat)
2. 5 actionable tips (numbered, each with a "why it works" subsection)
3. Common mistake to avoid
4. Quick-start checklist (bullet list)
5. Call-to-action: "Try one tip this week and share your result"

# SEO Requirements
- Primary keyword: "remote work productivity"
- Secondary keywords: "distributed team tips", "remote team management"
- Include keyword in H1, first 100 words, and one H2

# Tone
Conversational, authoritative, encouraging. Use "you" and "we." No jargon.

# Length
1,200–1,500 words

# Examples
Strong opening: "Last quarter, our distributed team cut meeting time by 40% — not by working harder, but by working differently."
Weak opening: "In today's fast-paced business environment, remote work has become increasingly popular."
```

**Why it works:** Structure + SEO + tone + examples = publication-ready content in one shot.

### 4. Customer Support Response

**Before:**
```
Help this customer with their billing issue.
```

**After:**
```
# Role
Customer support lead for a SaaS company. You are empathetic, solution-oriented, and brand-consistent.

# Customer Message
"[customer's message]"

# Context
- Customer tier: Pro plan ($49/mo)
- Issue: Charged twice for last month
- Policy: Refunds processed within 3–5 business days
- Tone: We take ownership, don't blame payment processors

# Output Format
1. Empathetic opening (acknowledge frustration)
2. Clear explanation of what happened
3. Exact next steps (refund timeline, confirmation email)
4. Preventive measure (how to avoid double charges)
5. Proactive goodwill offer (10% off next month OR extended trial)

# Constraints
- No jargon
- No "please contact support again" — this IS the resolution
- Keep under 150 words
- Sign off as "The [Product] Team"
```

**Why it works:** Empathy + clear steps + proactive goodwill = higher CSAT and retention.

### 5. Data Analysis

**Before:**
```
Analyze this sales data.
```

**After:**
```
# Role
Data analyst for an e-commerce business. You find actionable insights, not just describe the data.

# Dataset
[CSV or data summary]

# Analysis Requirements
1. Top 3 performing products by revenue
2. Underperforming products with recommendations
3. Week-over-week trend analysis
4. Anomalies or outliers worth investigating
5. One actionable recommendation for next month

# Output Format
Executive summary (3 sentences)
Key findings (bullet list with supporting numbers)
Recommendation (one paragraph)

# Constraints
- Round all numbers to 2 decimal places
- Use $ for USD, specify currency if different
- If data is insufficient for a section, state "Insufficient data — recommend collecting X"
- Avoid technical jargon; write for a non-technical founder
```

**Why it works:** Specific questions + output format = insights that drive decisions, not just charts.
